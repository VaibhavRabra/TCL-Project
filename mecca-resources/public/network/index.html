The multi-cloud network checklist

Score each item 0 (not sorted), 1 (partly) or 2 (clear answer). Below 16 out of 24 is a sign the network needs attention before more workloads move.

1. Traffic and paths

  1. Do you have a current map of traffic between sites, data centres and each cloud? Most performance complaints start with a path nobody drew.
  2. Does cloud-to-cloud traffic go direct? Traffic that returns through a data centre adds delay and cost.
  3. Are critical applications prioritised? Voice, payments and customer-facing apps should not compete with backups.

2. Performance

  1. Do you measure application response from the user's side? Link uptime alone hides slow applications.
  2. Is there a second path for every important site? Check that the two paths do not share the same cable route or provider.
  3. How long does a failover take, and when was it last tested?

3. Cost and contracts

  1. What do you pay per site per month, all in? Include circuits, devices, licences and support.
  2. Which contracts renew in the next 12 months? Renewals are the moment to simplify.
  3. How many providers do you manage? Each one adds a bill, a portal and an escalation path.

4. Operations and security

  1. Can one team see the whole network in one view?
  2. How long does a new site or cloud connection take? Days, weeks or a procurement cycle?
  3. Are security policies the same at every site and cloud entry point?
